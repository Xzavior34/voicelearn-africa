- **Language pairs represented:** en, pcm, en-pcm, en-yo (in the text fixtures)
- **Speaker country/accent (physical recording):** Nigeria / West African English

## 6. Code-Switching Evidence

**Honest current state: zero physical code-switched audio recordings exist.** All Pidgin/Yoruba/code-switching dataset entries are text-only fixtures with annotated language spans (`codeSwitchSpans`), used to validate the tutor's topic/intent handling on code-switched *text*, not to measure ASR accuracy on code-switched *speech*.

**PENDING HUMAN RECORDING:** `DATASET.md` Section 4 has step-by-step instructions for recording one genuine English/Nigerian-Pidgin sample (e.g. "I understand say negative times negative dey give positive, but why exactly e dey work like that?"), adding it to the dataset, and re-running the benchmark. Do not submit a code-switching accuracy claim until this is done — cite the text-fixture-only evidence honestly if it isn't.

## 7. Downstream Educational Evaluation

- **Ground-truth intent/topic baseline** (assumes perfect ASR, isolates the reasoning pipeline): Concept Accuracy 81.3% (26/32), Topic Accuracy 81.3% (26/32) — from `lib/benchmark/reports/intent-baseline-latest.json`, regenerate via `npm run benchmark`.
- **Automated regression coverage** (146 tests passing as of this audit): confirms the tutor never reuses a stale topic/answer across the specific sequence Math (Pidgin) → "Wetin be evaporation?" → "Why do plants need sunlight?" → affect/effect, plus rapid turns, follow-up questions, and turn-cancellation safety (`AbortController`/turn-guard).
- **End-to-end (real ASR → tutor) evaluation:** not yet measured — depends on Section 4's models actually running. Once `npm run benchmark:verify` reports `VERIFIED` for a model, its `downstream` field in `benchmark/results/raw-results.json` shows whether that model's actual transcript reached the correct concept/topic — this is the number that answers "does better ASR produce a better learning interaction," and it does not exist yet for any model in this repo's current state.

VoiceLearn Africa is positioned as a **low-stakes revision and homework companion used alongside classroom teachers, never in place of human educators** (see `RESPONSIBLE_AI.md`). ## 9. Known Limitations

- The physical audio dataset has **1 recording**. Any WER/CER measured from it is a single-sample case study, not a statistically powered claim about the models' general performance.
- **Zero physical code-switched audio recordings exist** as of this audit (Section 6).
- Two of the three local benchmark models (Whisper Base entirely; Whisper Tiny and Wav2Vec2 Base partially) do not have complete model files in this repository's current state — see `LOCAL_MODEL_SETUP.md`.
- Sahara requires `SAHARA_API_KEY`, which was not available in the environment this document was generated in.
- The live Vercel deployment was not tested as part of this audit (no network access to it from this environment) — test it yourself before submitting.
- Historical WER/CER figures in some of this repo's older docs are mutually inconsistent (see the stale-number notices added to `BENCHMARK_RESULTS.md`, `DEMO_SCRIPT.md`, `FINAL_PRODUCT_AUDIT.md`, `FINAL_SUBMISSION_READINESS.md`) — do not cite them; regenerate and cite fresh numbers instead.
